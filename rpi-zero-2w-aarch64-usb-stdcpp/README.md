## Build and run

```bash
./run.sh list              # build, then list the CTest cases (* = selected)
./run.sh                   # build, then run the selected tests (no hardware)
./run.sh usb_test         # one test, by directory name
./run.sh --hwd             # the selected tests, hardware cases included
./run.sh --hwd-only        # only the hardware cases
./run.sh all               # every registered case
./run.sh build             # configure + build only
./run.sh -c aarch64-rpi-zero-2w-cmake-gcc-debug
```

Configurations: `aarch64-rpi-zero-2w-cmake-gcc-debug`. The build folder is
`micro-os-plus-iii/tests/build/<configuration>/`. CTest cases are named
`<platform>-<test>-qemu|hwd|host`; the AArch boards add a `-reset` fixture before each
hardware case, and the QEMU SD-card tests add `-sd-make`/`-sd-remove`. CTest runs them
automatically.

**Hardware cases** need the board and the probe. CTest starts OpenOCD with the
platform's `openocd.cfg`; the test's `RESULT:` line, through semihosting, is the verdict.
Probe selection: `PROBE=jlink|olimex|cmsis-dap` (AArch Pi boards),
`UOS_HW_ADAPTER_SERIAL=<serial>` when several CMSIS-DAP probes are attached (serials:
`cat /sys/bus/usb/devices/*/serial`), `UOS_HW_ADAPTER_KHZ=<kHz>` for the clock.

Results: `build/<configuration>/ctest.xml` (JUnit) and `ctest.log` (full output).

## Adding to this workspace

| You add | Put it in | Picked up by |
| --- | --- | --- |
| a board test | `micro-os-plus-iii/tests/platforms/<platform>/tests/<name>/*.cpp` | the builder (`tests/board-tests/`) globs one test per folder |
| a test's build settings | the hooks in `.../platforms/<platform>/tests/tests.cmake` (`board_test_defines`, `_sources`, `_includes`, `_libs`, ...) | the builder |
| board code | `.../platforms/<platform>/src/`, `include/` | the platform library |
| a shared test for several boards | `micro-os-plus-iii/tests/sources/<name>/`, named in the platform's `UOS_TESTS_SOURCES` | the builder |

`./run.sh` re-runs CMake every time, so a new folder is noticed without removing the
build tree. A re-scaffold rebuilds the workspace from the source: keep tests you want to
last in the source repository.

## µTest++ (`--micro-test-plus`)

µTest++ 6.0.0 from `https://github.com/micro-os-plus/micro-test-plus-xpack.git` (v6.0.0) is in
`third_party/micro-test-plus/`; the board support (console, verdict, report file, cores) is in
`micro-os-plus-iii/tests/mtp/` (its README lists the defines and the SMP helpers).

| Platform | Status | Console | SMP boot | Starter tests |
| --- | --- | --- | --- | --- |
| `aarch64-rpi-zero-2w` | integrated | 1 | 1 | `mtp-example`, `mtp-args`, `mtp-smp` |

A µTest++ test is a folder `micro-os-plus-iii/tests/platforms/<platform>/tests/mtp-<name>/`:
copy `mtp-example/` (or `mtp-smp/` for a multi-core test). Every `mtp-*` folder links
µTest++ through the block at the end of the platform's `tests/tests.cmake`.

Each `mtp-*` case gets its name as `argv[0]` and `--output-file <report>`: the complete
TAP report is `micro-os-plus-iii/tests/build/<configuration>/mtp-reports/<ctest name>.tap`
(written through semihosting under QEMU and on the board). The registration helpers in
`micro-os-plus-iii/tests/cmake/uos-tests-run.cmake` carry the change, marked
`SCAFFOLD µTest++`; other tests are unchanged.

## StateOS stdc++ (`--stdcpp`)

The StateOS stdc++ package adapted to µOS++ III is in `third_party/stateos-stdc++/`
(from the copy bundled with micro-os-scaffold): the GCC gthread
layer (`std::thread`, `std::mutex`, `std::condition_variable`, `std::call_once`),
`std::future`/`promise`/`async`, the clocks over the kernel clock, emulated
`thread_local`, and C++20 `<barrier>`, `<latch>`, `<semaphore>`.

| Platform | stdc++ | Starter test |
| --- | --- | --- |
| `aarch64-rpi-zero-2w` | integrated | `micro-os-plus-iii/tests/platforms/aarch64-rpi-zero-2w/tests/mtp-stdcpp` |

To use it from another test, return `stateos-stdc++` from the library hook in the
platform's `tests/tests.cmake`, as the `mtp-stdcpp` branch does. On the RP2040/RP2350
a `std::atomic` read-modify-write does not exclude the other core: use the package's
mutexes or `mtp_board::atomic_add ()` there.
