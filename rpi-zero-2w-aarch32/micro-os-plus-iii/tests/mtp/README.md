# µTest++ board support for micro-os-plus-iii/tests

Generated by `micro-os-scaffold --micro-test-plus` from https://github.com/micro-os-plus/micro-test-plus-xpack.git (v6.0.0), µTest++ 6.0.0.

| File | What it does |
|---|---|
| `mtp_board.hpp`, `mtp_board.cpp` | the runner, the self-registering suites, the console for µTest++'s report, the report file, the RESULT line, the cores, the cross-core helpers |
| `mtp_semihosting.hpp` | the raw semihosting calls the report needs: `SYS_GET_CMDLINE`, `SYS_OPEN`, `SYS_WRITE`, `SYS_CLOSE` |
| `mtp_startup.hpp` | the µOS++ start-up, for the boards whose tests carry their own (`MTP_CARRY_STARTUP=1`); it reads `argc`/`argv` from the debugger before starting the main thread |

Each board that uses it has a µTest++ block in `../platforms/<platform>/tests/tests.cmake`, which sets:

| Define | Meaning |
|---|---|
| `MTP_CONSOLE=1` | stdout replaced by a stream to the UART (`putc_uart`) and to semihosting (`SYS_WRITE0`, batched) |
| `MTP_CONSOLE=2` | a strong `_write ()` to the UART (`uart::write`) and to semihosting (`hw_result::semi_write0`, batched) |
| `MTP_CONSOLE=3` | hosted: stdout is the host's |
| `MTP_SEMIHOST_ARGS=1` | Cortex-M: strong `os_startup_initialize_args ()` reads the command line from the debugger |
| `MTP_SEMIHOST_ARGS=2` | AArch32/AArch64: `mtp_startup.hpp` reads it before creating the main thread |
| `MTP_SEMIHOST_ARGS=0` | hosted: the process arguments |
| `MTP_HAS_SMP_BOOT=1` | `release_cores ()` through the port's test-smp-boot helpers (AArch32/AArch64) |
| `MTP_HAS_SMP_BOOT=2` | `release_cores ()` through `multicore::launch_core1` (RP2040/RP2350) |
| `MTP_UART_INIT=1` | the board's start-up leaves the UART off: `start ()` calls `uart::init (board::UART_BAUD)`, as its tests do |
| `MTP_NANO_PRINTF=1` | newlib-nano: the printf family is wrapped to drop the `z` of `%zu`, and `_printf_float` is linked |
| `MTP_CARRY_STARTUP=1` | `mtp_startup.hpp` provides `main ()` and the start-up hooks |
| `MTP_HOSTED` | no linker heap to check (the host C library owns it) |

The report file is written through semihosting, whatever the port:
`-Wl,--wrap=fopen` (added by the same block) sends the reporter's
`fopen (--output-file)` to `mtp_semihosting::open ()`, so no board needs
`_open ()`/`_write ()` file-system calls. The CTest runner passes the path
in the command line (`arm semihosting_cmdline --output-file <path>` on a
probe, `-semihosting-config ...,arg=...` under QEMU).

A suite is a `mt::static_suite` at namespace scope, in its own file:

```cpp
mt::static_suite suite_basics{ "02 - Basics", mtp_board::runner (),
                               [] (mt::suite& ts) { ... } };
```

Nothing lists the suites: run_suites () discovers every static suite of
the image and runs it sorted by name.

The helpers for SMP tests (`mtp_board.hpp`):

| Helper | What it does |
|---|---|
| `release_cores ()`, `suite_cores` | start the other cores, pin the runner to core 0, check they joined |
| `cpu_id ()` | the core running the caller |
| `irqs_masked ()` | this core's interrupt mask (DAIF.I, CPSR.I, PRIMASK/BASEPRI) |
| `sync_method ()` | the board's cross-core read-modify-write: the exclusive monitor (LDAXR/STLXR, LDREX/STREX) or the RP2 SIO hardware spinlocks |
| `spinlock`, `atomic_add ()` | a lock and an atomic add between cores, through `sync_method ()` |

On the RP2040/RP2350, `std::atomic` read-modify-write does not exclude the other core
(their exclusive monitor is per core); use `spinlock`, `atomic_add ()` or the kernel there.

A new µTest++ test is a directory `../platforms/<platform>/tests/mtp-<name>/`: copy `../platforms/<platform>/tests/mtp-example/`
(or `../platforms/<platform>/tests/mtp-smp/` for a multi-core test).
